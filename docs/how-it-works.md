# 어떻게 동작하나요

Geulte를 쓸 때 가장 헷갈리는 부분은 **“서버를 내가 켜 둬야 하나?”** 입니다.  
결론부터 말하면, **블로그 본문을 보여 주는 데 상시 서버는 필요 없습니다.**

## 세 층으로 나누어 보기

```text
[1] 필수 — 정적 사이트
    마크다운 → 빌드 → HTML/CSS/JS 파일 → 아무 정적 호스트

[2] 권장 풀스택 (원할 때)
    GitHub에 푸시 → 자동 빌드 → Vercel에 배포
    + Supabase (조회수·필터·대시보드용 DB)

[3] 없어도 되는 기능
    sync, 조회수, 대시보드, 프로덕션 조합 필터
```

### 1) 필수: 정적 사이트 (SSG)

**SSG(Static Site Generation, 정적 사이트 생성)** 이란:

> 방문자가 들어올 때마다 글을 DB에서 꺼내 조립하는 게 아니라,  
> **미리** HTML 파일로 만들어 두고, 방문자가 오면 그 파일을 그대로 보내 주는 방식입니다.

비유하면:

- 동적 사이트 ≈ 손님이 올 때마다 주방에서 요리  
- 정적 사이트 ≈ **도시락을 미리 싸 두고** 손님이 오면 꺼내 줌

Geulte의 `geulte build`가 그 “도시락 싸기”입니다. 결과물 폴더가 보통 `dist/` 입니다.

### 2) 권장 풀스택: GitHub + Vercel + Supabase

공식 스캐폴드(초기 템플릿)가 안내하는 **편한 한 줄 경로**입니다.

- **GitHub**: 글과 설정을 저장하는 원격 창고 + 자동 빌드 스위치  
- **Vercel**: 정적 파일 배포 + (필요 시) 짧은 서버 함수(`api/filter` 등)  
- **Supabase**: 클라우드 Postgres DB. 조회수·조합 필터 등에 사용

이것은 **“유일하게 되는 방법”이 아니라 “문서가 제일 잘 안내하는 방법”** 입니다.

### 3) 없어도 되는 기능

아래가 없어도 **글 읽기·목록·⌘K 검색·다크모드** 같은 핵심은 동작합니다.

| 기능 | 없으면 |
| :--- | :--- |
| Supabase sync | DB에 글 메타가 안 올라감 |
| 조회수 / 대시보드 | 통계 페이지가 약해지거나 안 나옴 |
| 프로덕션 조합 필터 | `/posts` 필터가 API 없이 실패할 수 있음 (로컬 `geulte dev`에서는 목 API로 가능) |

## 로컬 `dev` vs 배포

| | `geulte dev` | `geulte build` 후 배포 |
| :--- | :--- | :--- |
| 목적 | 내 컴퓨터에서 미리보기 | 세상에 공개 |
| 서버 | 잠깐 켜 두는 개발용 | 상시 앱 서버 불필요 (정적 호스트) |
| 라이브 리로드 | 있음 (파일 바꾸면 새로고침) | 없음 (다시 빌드·배포) |

## 데이터가 흐르는 그림

```text
content/posts/*.md  (당신이 쓴 글)
        │
        ▼
   geulte build
        │
        ├──► dist/           ← 웹에 올라가는 정적 파일
        │
        └──► (선택) Supabase ← sync 할 때만
```

브라우저 검색(⌘K)은 빌드 때 만든 인덱스를 **방문자의 브라우저**에서 돌립니다.  
그래서 검색만 쓰려고 Supabase를 켤 필요는 없습니다.
